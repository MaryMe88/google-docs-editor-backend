# Torch security audit — 2026-10-06

## Назначение

Документ фиксирует результаты аудита Torch, установленного в проекте.
Torch не был покрыт `pip-audit` (пакет установлен из отдельного
CPU-индекса PyTorch), поэтому по нему не было данных в основном отчёте
issue #35. Это исследовательская итерация — **пакеты не обновляются**,
только фиксируется фактическое состояние.

## Проверка кода на опасные паттерны

Grep по `src/`, `tests/`, `scripts/` на предмет опасных вызовов:

| Паттерн | Результат |
|---|---|
| `torch.load` | **не найден** |

| `from_pretrained` | **не найден** |
| `safetensors` | **не найден** |

**Что это значит.** Наиболее опасные векторы Torch-уязвимостей
(десериализация недоверенных файлов через `torch.load` и `pickle`)
в коде проекта отсутствуют. Мы не загружаем пользовательские модели,
чекпоинты или pickle-файлы.

## Как загружается модель эмбеддингов

`src/semantic_index.py`:

    from sentence_transformers import SentenceTransformer
    self._model = SentenceTransformer(self.model_name)

- `self.model_name` — параметр с дефолтом `"cointegrated/rubert-tiny2"`.
- Пользователь API не может подменить имя модели через запрос.
- Параметр `trust_remote_code=True` **не передаётся** — код модели не выполняется.
- Модель публичная, из официального Hugging Face-пространства.
- Загрузка **ленивая** — происходит только при `deep_semantic_search=True`, который по умолчанию выключен.

## Ручная проверка advisories

Проверены источники:

- GitHub Security Advisories PyTorch: https://github.com/pytorch/pytorch/security/advisories
- OSV (база уязвимостей): https://osv.dev/list?ecosystem=PyPI&q=torch
- NVD (база CVE): https://nvd.nist.gov/vuln/search

**Результат:** в публичных advisories, затрагивающих Torch **2.5.0**
в нашей конфигурации (CPU-only, без `torch.load`), критичных
уязвимостей не обнаружено.

### Что именно проверялось (для протокола)

Наиболее значимые записи, которые могут касаться 2.5.0:

- **CVE-2025-32434** (GHSA-53q9-r3pm-6pq6) — RCE через `torch.load(weights_only=True)`,
  обход безопасного режима. Исправлено в **2.6.0**. Уязвимы версии ≤ 2.5.1.
  **В нашем коде `torch.load` не используется**, поэтому вектор недостижим.
- **CVE-2025-2953** (GHSA-3749-ghw9-m3mg) — проблема в `torch.load`/десериализации.
  Требует загрузки недоверенного чекпоинта. У нас такой сценарий отсутствует.
- **CVE-2025-46148** — некорректные результаты `nn.PairwiseDistance` при `eager`.
  Не связано с безопасностью, не влияет на загрузку модели.
- **CVE-2025-63396** — DoS через пропуск `profiler.stop()`. Требует использования
  профайлера, которого в проекте нет.

Ни одна из записей не достигается через наш код или внешний HTTP-запрос.

## Решение

**Остаёмся на Torch 2.5.0+cpu. Никаких изменений в `requirements.txt`
и в коде проекта.**

## Обоснование

1. **Опасные векторы недостижимы.** `torch.load`, `pickle`,
   `trust_remote_code` и загрузка пользовательских файлов в коде
   отсутствуют.
2. **Модель не подконтрольна клиенту.** Имя модели жёстко задано
   дефолтом, пользователь API не может его подменить.
3. **Deep semantic search выключен по умолчанию.** В обычном
   retrieval-режиме модель не загружается вообще.
4. **Сборка CPU-only.** Уязвимости, связанные с CUDA-драйверами
   и GPU-памятью, к нам не применимы.
5. **Актуальных критичных advisory нет.** Ручная проверка трёх
   независимых источников подтвердила это.

## Остаточные риски

- **`torch` не покрыт `pip-audit`** из-за отдельного CPU-индекса.
  Это сохраняется как известное ограничение инструмента аудита.
  В итерации 8 (повторный полный аудит) надо проверить, есть ли
  способ добавить Torch в отчёт — например, через `--extra-index-url`
  в самом pip-audit или через отдельный вызов для CPU-пакета.
- **Версия 2.5.0 не самая свежая.** Более новые версии содержат
  патчи безопасности для других сценариев использования, которые
  к нам не применимы. Обновление Torch отдельной задачей не
  планируется, так как требует проверки совместимости
  с `transformers` и `sentence-transformers`.

## Что делать в будущем

При обновлении ML-стека в итерациях 6–7 дорожной карты уязвимостей:

1. Проверить, требуется ли обновление Torch для новых версий
   `transformers` и `sentence-transformers`.
2. Если да — обновить Torch вместе с ML-стеком, отдельным PR,
   с полным baseline и golden-тестами retrieval.
3. После обновления — повторить эту проверку (grep опасных паттернов,
   ручной аудит advisories) и обновить этот документ.
