## Уроки для следующего исполнителя

- **PS 5.1 + `importlib.metadata`** — версии пакетов читать через `importlib.metadata.version("pkg")`; `pkg.__version__` может отсутствовать (особенно если импорт мокается).
- **`python -m pip_audit`** (underscore), не `pip-audit` — иначе `No module named pip-audit`. Или CLI: `.venv-reliability\Scripts\pip-audit.exe`.
- **`pip-audit` + torch**: CPU-wheel из PyTorch-индекса не покрывается. Это компенсируется `verify_torch.py` (version guard) и ручным `torch-risk-assessment.md`. **Не** считать «pip-audit clean» полным аудитом.
- **CodeQL `py/incomplete-url-substring-sanitization`** ловится на `"x" in list`. `set(list) == {…}` — не ловится. Замена паттерна = настоящий fix, не обход.
- **Markdown hard break** (два пробела перед `\n`) = **намеренный** формат в `torch-risk-assessment.md` metadata. `git diff --check` на `.md` даёт ложные срабатывания. Решение: принять, задокументировать; при желании — `.gitattributes`.
- **`torch 2.12.1+cpu` тянет `setuptools<82`** — транзитивный downgrade `84.2.1 → 81.0.0`. Ожидаемо; `security.yml` уже игнорирует 3 advisory setuptools как build-time-only.
- **CVE-2026-24747 недоказуем grep'ом** «torch.load не вызывается» — положительное доказательство через `pickletools` / `.safetensors`-кеш надёжнее.
