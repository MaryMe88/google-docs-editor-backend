\# Reproducible Torch installation — 2026-10-10



\## Назначение



Документ фиксирует, что установка Torch в проекте теперь

воспроизводима: одинаковый результат на Windows, Linux, Render

и в CI, независимо от состояния сети и порядка индексов pip.



Итерация 4 новой дорожной карты остаточных security-работ (issue #35).



\## Проблема



До этой итерации в `requirements.txt` было:

\--extra-index-url https://download.pytorch.org/whl/cpu

...

torch==2.5.0,<3.0





\### Что не так



\*\*1. Два индекса — два разных Torch 2.5.0.\*\*



\- В обычном PyPI лежит `torch 2.5.0` — CUDA-сборка, \~2 ГБ.

\- В CPU-индексе `download.pytorch.org/whl/cpu` лежит

&#x20; `torch 2.5.0+cpu` — CPU-сборка, \~200 МБ.



Запись `torch==2.5.0` (без `+cpu`) \*\*матчит оба варианта\*\*.

По PEP 440 суффикс `+cpu` считается «больше», чем отсутствие

суффикса, поэтому pip выбирает `2.5.0+cpu`. Это спасает нас

сегодня, но не является гарантией.



\*\*2. Если CPU-индекс недоступен.\*\*



Сеть, файрвол, outage CPU-индекса — pip молча возьмёт

`torch 2.5.0` из PyPI. На Render (free tier, без видеокарты)

CUDA-сборка либо не запустится, либо превысит лимит памяти

образа.



\*\*3. Диапазон `<3.0` вводит в заблуждение.\*\*



`torch==2.5.0,<3.0` — избыточное условие. Смысл тот же, что

`torch==2.5.0`, но синтаксис намекает, что можно ставить

диапазоны. Будущий разработчик может заменить на

`torch==2.5.0,<4.0` и случайно получить 2.6+ без проверки

совместимости с `transformers 4.57.6` и

`cointegrated/rubert-tiny2`.



\## Решение



Одна строка в `requirements.txt`:



torch==2.5.0+cpu





\### Почему это работает



\- `+cpu` — это \*\*часть версии\*\* в PEP 440. Запись

&#x20; `torch==2.5.0+cpu` матчит \*\*только\*\* запись `2.5.0+cpu` из

&#x20; CPU-индекса. Запись `2.5.0` из PyPI (без суффикса) —

&#x20; \*\*не матчится\*\*.

\- Если CPU-индекс недоступен, pip \*\*падает с ошибкой\*\*.

&#x20; Это лучше, чем молча поставить «не ту» сборку: ошибка видна

&#x20; сразу на этапе install, деплой не ломается в проде.

\- Убрали `<3.0` — версия пинуется точно.



\### Что не менялось



\- Сама версия Torch: \*\*2.5.0\*\* (проверена в итерации 3 —

&#x20; `docs/security/2026-10-torch-audit.md`).

\- CPU-индекс в `--extra-index-url`.

\- Все остальные зависимости.

\- Runtime-код, KB, промпты.



\## Проверки



Создан `tests/test\_torch\_install\_contract.py` (10 тестов):



1\. `torch.\_\_version\_\_` заканчивается на `+cpu`.

2\. `torch.version.cuda is None`.

3\. `torch.cuda.is\_available() is False`.

4\. `torch` импортируется.

5\. В `requirements.txt` есть строка `torch==`.

6\. Строка содержит `+cpu`.

7\. Строка не содержит запятую (диапазон версий).

8\. Строка соответствует формату `torch==X.Y.Z+cpu`.

9\. В `requirements.txt` есть адрес CPU-индекса.

10\. `sentence-transformers` действительно требует `torch`.



Baseline: \*\*582 passed\*\* → \*\*592 passed\*\* (+10 новых тестов).



\## Остаточные риски



\### `pip install` может поставить CUDA-сборку через lock-файл



Если в будущем появится `requirements.lock` (например, через

`pip-tools` или `uv`), надо убедиться, что в нём тоже

`torch==2.5.0+cpu`. Сейчас lock-файла нет — только

`requirements.txt` и `requirements-dev.txt`.



\### Render может тянуть свой индекс



Если Render когда-нибудь добавит в build-среду свой индекс

PyTorch (пока такого нет), `--extra-index-url` всё равно

останется первым в файле, и CPU-сборка будет приоритетной.

Явный `+cpu` в пине гарантирует, что CUDA-сборка не будет

выбрана случайно.



\### Локальные среды разработчиков



У разработчиков без интернета к CPU-индексу `pip install

\-r requirements.txt` теперь \*\*упадёт\*\*. Это осознанный

компромисс: лучше явная ошибка, чем неверная сборка.
