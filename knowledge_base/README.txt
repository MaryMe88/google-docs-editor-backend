# База знаний — добавление нового файла

Этот документ содержит чек-лист действий при добавлении нового файла в `knowledge_base/`.

## Чек-лист

1. **Определите тип файла**  
   - Это приём в существующий блок? (например, пополнение `marketing_templates` или `editorial_techniques`)  
   - Или это новый жанр / новый блок (тогда требуется регистрация в коде)?

2. **Скопируйте эталонный файл**  
   Для жанровых блоков используйте `marketing_email.json` как образец.  
   Убедитесь, что файл содержит поля:
   - `tags` — список тегов для ретривала
   - `scope` (опционально) — описание области применения
   - `example_disclaimer` (опционально) — предупреждение о примерах
   - `templates[]` или аналогичный массив записей

3. **Опишите файл в `FILE_RULES` генератора**  
   - Отредактируйте `scripts/generate_kb_manifest.py`, добавьте запись в словарь `FILE_RULES`.  
   - **Не редактируйте `kb_manifest.json` вручную** — он перегенерируется.

4. **Если создаётся новый блок** — добавьте его сразу в четырёх местах:
   - `LimitsConfig` (в `src/config_types.py`) — добавьте поле с именем блока
   - `KnowledgeBudget` (там же) — добавьте соответствующее поле
   - `_LEVEL_BLOCKS` (в `prompt_builder.py` или в `resolve_prompt_features`) — укажите, на каких уровнях знаний блок доступен
   - `KB_BLOCK_REGISTRY` (в `prompt_builder.py`) — зарегистрируйте новый блок

5. **Проверьте теги**  
   - Используйте только существующие теги из реестра (см. `tag_registry.py` и существующие файлы).  
   - Если нужен новый тег — добавьте его одновременно с записями, которые его используют.

6. **Напишите тесты**  
   - Добавьте пару тестов «фраза есть при overlay / нет без overlay» (см. `test_architecture_invariants.py`).  
   - Добавьте тест на корректность `id` выбранной записи (если блок использует выборку по ID).

7. **Запустите валидацию и тесты**  
   - `python validate_kb_tags.py`  
   - `pytest tests/ -v`  
   - **Сравните список WARNING-предупреждений до и после** — новые тесты могут выявить скрытые рассинхроны.

8. **Закоммитьте изменения** отдельным коммитом с понятным сообщением.

---

## Примечания

- Всегда используйте генератор для обновления манифеста, чтобы избежать ручных расхождений.  
- Если вы меняете структуру существующего файла — убедитесь, что `block_type` (list/dict) в манифесте соответствует реальному формату.
